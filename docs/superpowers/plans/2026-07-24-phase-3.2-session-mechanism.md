# Phase 3.2: Real Session Mechanism Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace client-side sessionStorage auth with server-side verified sessions. Every authenticated API route must verify the session server-side (from a signed cookie or JWT), not trust any user ID, role, or identity field sent in the request body or headers.

**Architecture:** 
1. Audit all API routes to identify those trusting client-sent identity data
2. Update vulnerable routes to use getSessionFromRequest from src/lib/session.ts
3. Ensure login/register routes properly set session cookies (they already do)
4. Verify that clearing sessionStorage doesn't log out users with valid session cookies
5. Test that expired/invalid session cookies are rejected
6. Verify users cannot access other users' data by modifying IDs in requests

**Tech Stack:** TypeScript, Next.js API Routes, session.ts utilities
